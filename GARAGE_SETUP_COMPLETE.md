## 🔧 Troubleshooting

### If containers stop or restart

The Garage data is stored in tmpfs (temporary filesystem), so it persists while containers are running but is lost on container removal. To maintain your data and credentials:

- Use `docker-compose restart` instead of `down` + `up`
- Or note your credentials and reconfigure after recreation

### If permissions are denied

Grant permissions manually using the Garage CLI:

```bash
docker exec garage /garage bucket allow --read --write metricsutilitys3 --key GK160f780fdab0f547be610987
```

### If you need fresh credentials

1. Stop and remove all containers:
   ```bash
   cd tools/docker
   docker-compose down
   ```

2. Start fresh:
   ```bash
   docker-compose up -d
   ```

3. Get new credentials from logs:
   ```bash
   docker logs docker-garage-setup-1 | grep -A 3 "Generated Key"
   ```

## ✨ Key Differences from MinIO

1. **Key IDs**: Garage generates key IDs starting with "GK" (e.g., `GK160f780fdab0f547be610987`) instead of allowing custom IDs like "myuseraccesskey"

2. **Ports**: 
   - Garage S3 API runs on port 3902 (mapped to 9000 for compatibility)
   - Admin API on port 3900
   - RPC on port 3901

3. **Management**: Use Garage CLI (`docker exec garage /garage`) or HTTP Admin API
